# 僵尸寮 QQ 群消息检查：NapCatQQ Desktop 方案

OAS 已改回外接 OneBot。内置扫码和自动连接已停用，功能默认关闭；原先已启用的配置保留启用状态。旧配置中的 builtin_qq=true 会被归一化成 false，避免继续使用失败的内置登录。

## 最简单的接入方式

使用 NapCatQQ Desktop Windows 图形管理器，在其中选择 NapCat。本次只需要 HTTP 服务端，OAS 到点查询群历史消息；不需要 WebSocket、HTTP 客户端上报或额外机器人应用。

### 1. 安装管理器

官方下载：[NapCatQQ Desktop Releases](https://github.com/NapNeko/NapCatQQ-Desktop/releases)。

选择 `NapCatQQ-Desktop-<版本>-x64.msi`，不要选择名字带 watch-v 的远程监控工具。安装包从上述官方 Releases 下载，本仓库不附带安装包。

双击安装包安装，打开 NapCatQQ Desktop。管理器支持图形化安装 QQ、框架等组件，并管理账号启动/停止。

### 2. 登录 QQ

在管理器按组件安装引导准备 Windows QQ 与 NapCat，创建本机账号配置，框架选择 **NapCat**，启动并按提示用手机 QQ 扫码。

登录的 QQ 账号必须已经加入目标群。OAS 不需要 QQ 密码；扫码在 NapCat / QQ 一侧完成。普通 QQ 已登录不等于 NapCat 已启动，管理器中的账号也需要正常在线。

### 3. 创建一个 HTTP 服务端

优先在 Desktop 该账号的连接配置中创建并保存；如果进入 NapCat 自己的 WebUI，管理地址与密码取启动日志。NapCat WebUI 默认为 `http://127.0.0.1:6099/webui/`，端口被占用时可能变化。

创建 **HTTP 服务端**（不是 HTTP 客户端），参数：

| 项目 | 填写值 |
| --- | --- |
| 启用 | 开启 |
| 监听地址 | 127.0.0.1 |
| 端口 | 3000（被占用时另选端口） |
| Token | 设置一个自定义访问令牌 |
| 消息格式 | array |

保存，并确保 HTTP 服务端已启用。Desktop 与 NapCat WebUI 管理密码、HTTP 服务端 Token 是不同的凭据；OAS 需要的是 **HTTP 服务端 Token**。

### 4. 填写 OAS 僵尸寮配置

重启 OAS 后台并刷新设置页面，使修改后的配置字段显示。进入僵尸寮的「QQ群消息检查」：

| OAS 字段 | 填写值 |
| --- | --- |
| 启用QQ群消息检查 | 开启 |
| 群历史消息API地址 | http://127.0.0.1:3000 |
| 历史消息API访问令牌 | 上一步 HTTP 服务端的 Token |
| 监听群号 | 目标群号码 |
| 监听成员QQ号 | 发布通知的成员 QQ 号码 |
| 放行关键词 | 例如 福利道馆已开启 |
| 排除关键词 | 按需填写，例如 未开启\|还没开 |
| 未匹配后等待分钟数 | 例如 3 |
| 每天最大未匹配次数 | 例如 10 |
| 重置当天检查次数为0次 | 需要清零时勾选保存，一次性操作 |

「事件上报签名密钥」在最简历史查询方案中留空。这里不填 NapCat WebUI 的 6099 端口。

启用僵尸寮任务调度，首次使用将「任务运行时间」安排到想开始检查的时间。保持 NapCat 在线及 OAS 后台运行。实际检查时间以僵尸寮任务的「任务运行时间」为准；点击「立即执行」或手动修改任务时间后，QQ 检查跟随该时间，不受旧的重试时间拦截。QQ 检查不再有独立的每日开始时间，旧配置中的该字段会被忽略。

## 运行规则

启用「启用QQ群消息检查」时才执行 QQ 消息检查；未启用时直接按福利寮名单搜索道馆。匹配后进入道馆流程。

按北京时间判断当天。到点后先查消息缓存，未匹配则调用 NapCat `/get_group_msg_history` 补读，筛选指定群和成员的当天文字消息。包含任一放行关键词且同条消息不含排除关键词才继续道馆。

未匹配或历史接口出错才累计一次。只有未到上限时，按实际检查时间加「未匹配后等待分钟数」重新运行道馆任务，跨午夜也遵循此间隔。匹配成功不消耗次数。次数耗尽时结束本轮任务，由道馆原调度逻辑根据调度器的「任务成功后设定经过 X 时间后执行」和「设置任务执行时间」计算下次运行时间；道馆执行成功和任务异常也继续沿用原调度处理，不由 QQ 检查指定时间。当天已达到上限时，晚到消息不会重新放行。

每日未匹配次数保存到 `config/dokan_qq_messages.db`，重启和立即执行不清零。需要重新检查时，在当前账号的道馆「QQ群消息检查」中勾选保存「重置当天检查次数为0次」，当天次数和等待状态立即重置，保存值自动恢复关闭；消息缓存、其他账号次数及当前任务运行时间不变。随后可点击僵尸寮「立即执行」，未匹配将从第 1 次重新计数。

QQ 检查只作为道馆入口条件。匹配后进入道馆流程：游戏启动、异常处理、狭间暗域周规则、两馆间 15 分钟等待和完成后的调度均保持原逻辑。游戏未启动等异常交回原来的处理器，不会被 QQ 检查标记成“当天结束”。旧版本错误留下的 finished 状态在下次读取时自动恢复，保留已有次数和消息。

历史每页默认 100 条、最多 5 页，页数可配置。消息量很大或协议端未能补读的记录可能超出查询范围，未找到时继续按未匹配重试。排除词只作用于同一条消息，后续另一条“取消”不会撤销此前已满足的消息。

## 实时接收（未移植）

本仓库移植时未带上 `module/server/dokan_qq_router.py` 与实时上报页面，因此只有「历史查询」这一种方式可用。

## 排查

- HTTP 连接失败：检查 NapCat 在线、HTTP 服务端已启用、地址端口正确；不要填 WebUI 管理端口。
- 401 / 403：OAS Token 必须与 HTTP 服务端 Token 完全一致。
- 读到消息仍不放行：核对群号、成员 QQ 号、北京时间日期、关键词和排除词。
- 当天已耗尽次数：可勾选保存「重置当天检查次数为0次」后立即执行；手动重启不会清零，跨日首次检查自动清零。
- 不要为测试直接运行有匹配公告的道馆任务，它可能进入游戏；可先在 NapCat API 调试台调用只读 `get_login_info` 和 `get_group_msg_history`。

OAS 原内置登录地址 `/dokan/qq/login` 现在显示接入说明。没有自动安装管理器、登录 QQ 或发送群消息；真实接收仍需扫码后联调。

## SnowLuma

同一个 Desktop 管理器也能运行 SnowLuma，但本次按 NapCat 设置。SnowLuma 的历史分页参数与 NapCat 不同，现有实现尚未完成该分页适配；不要直接当作已经验证的替代方案。
